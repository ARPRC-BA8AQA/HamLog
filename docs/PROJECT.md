# HamLog Web 项目文档

> 业余无线电台日志管理系统 · 前后端分离 Web 重构版
> 版本:Release 2.0.0 ｜ 协议:GPL-3.0
> 仓库:https://github.com/ARPRC-BA8AQA/HamLog
> 架构:Flask 后端 API + 静态前端(front 目录)

---

## 1. 项目简介

HamLog Web 是原 HamLog 桌面应用的全面重构版本,从单机 PyQt6 桌面应用演进为**前后端分离的 Web 应用**。后端基于 **Flask** 提供 RESTful 风格 API(统一 POST),前端为放置于 `front/` 目录的静态网页(html/css/js,可选 php)。所有原有功能在 Web 形态下重新实现并优化,同时新增 QSL 卡片设计器、插件系统、AES-256 加密、NTP 授时等能力。

目标:在保留单机本地使用习惯的同时,获得 Web 的跨设备访问、易扩展、易部署优势,并显著提升稳定性、兼容性与安全性。

---

## 2. 重构目标与原则

| 维度 | 目标 |
|------|------|
| 架构 | 前后端分离;后端 Flask 开放 API;前端静态资源放 `front/` |
| 安全 | JWT 可选认证、CORS、CSRF 防护、SQL 参数化查询、AES-256 可选加密 |
| API | 统一 POST 请求;标准 JSON 响应(含状态码);独立 API 文档 |
| 日志 | 单一 Python 文件统一记录;可选等级;崩溃日志必保 |
| 授时 | 自动获取管理员权限连接标准授时服务器,保证时间正确 |
| 扩展 | 后端插件系统 + 插件中心(用户可加源,含官方默认源);插件隔离 |
| QSL | 全新卡片设计器(类 PPT);私有/公共格式导出;版本兼容;10s 自动保存;一键填充;PDF 打印 |
| 兼容 | 新旧版本数据兼容,能读多少读多少 |
| 稳定 | 插件与业务隔离,异常不致全局崩溃 |

## 3. 功能特性

### 3.1 核心业务(沿用并优化)
- **QSO 日志**:录入/编辑/查看/删除,呼号自动大写,本地时间自动转 UTC 存储
- **智能搜索**:呼号、QTH、设备、备注多字段模糊搜索
- **实时统计**:总通联数、今日通联数
- **QSL 管理**:卡片收发状态与日期追踪
- **本台配置**:呼号、姓名、QTH、网格、默认模式/功率/设备
- **ADIF 导出**:按日期/波段/模式筛选,符合 LoTW 字段要求
- **LoTW 上传**:调用 TQSL 签名生成 .tq8,HTTP POST 上传至 ARRL
- **QRZ 查询**:爬虫获取国家/QSL/LoTW/eQSL/头像/ Biography(登录态可选)
- **网络延迟监测**:多节点 Ping 实时显示
- **在线更新**:版本检查、更新日志、安装包下载(ghproxy 镜像)
- **主题**:深色/浅色切换

### 3.2 新增:QSL 卡片设计器
- **类 PPT 网页设计器**:画布、图层、拖拽、对齐吸附
- **基础图形**:矩形、圆、线条、文字、图片、二维码
- **背景图**:自定义上传或内置图库
- **智能一键填充**:指定位置绑定数据类别(呼号/日期/频率/信号/本台信息等),通联数据自动填充
- **导出**:
  - 私有格式 `.hamqsl`:可在其他设备导入继续编辑
  - 公共格式:PDF(打印)、PNG 图片;若能获取原始数据亦可回导
- **自定义大小**:自定义画布尺寸与打印纸张
- **自动打印 PDF**:一键生成可打印 PDF
- **版本兼容**:格式带 schema 版本号,新旧版本能读多少读多少
- **10s 自动保存**:有更新时自动保存

### 3.3 新增:插件系统
- 插件(英文 **plugin**)为一个或多个 `.py` 文件,放置于plugin文件夹下
- **插件中心**:用户可自行添加插件源,内置官方默认源
- **规范开发**:统一插件 API、manifest 元数据、权限声明(详见 [PLUGIN_DEV.md](PLUGIN_DEV.md))
- **敏感权限提醒**:涉及文件/网络/系统/数据库的权限明确标注并需用户确认
- **语法审核**:加载前 `ast` + `py_compile` 审核,语法错误不允许加载并提示
- **业务隔离**:插件在沙箱中运行,插件出错不会导致全局崩溃

### 3.4 新增:安全与系统
- **JWT 认证(可选)**:配置开关;关闭时不降权(默认全权);开启时登录签发 Token
- **CSRF 防护**:提供 CSRF 令牌机制
- **CORS**:可配置允许的来源
- **AES-256 加密(可选)**:对敏感信息加密,需用户手动开启
- **NTP 授时**:自动获取管理员权限连接标准授时服务器,校正系统时间
- **统一日志**:单一文件统一记录,可选等级,崩溃日志必保

## 5. 认证与权限模型

| 配置 `auth.enabled` | 行为 |
|---------------------|------|
| `false`(默认) | 不启用认证,**不降权**,所有请求视为全权(管理员),无需 Token |
| `true` | 启用 JWT 认证;用户名密码登录签发 access/refresh Token;受保护接口需 `Authorization: Bearer <token>` |

- Token 由登录接口签发,前端存储并随请求携带
- 关闭认证时,后端装饰器自动放行,业务逻辑无感
- 权限分级:管理员 / 普通用户;关闭认证时默认管理员

## 6. 安全设计

- **CORS**:`flask-cors`,允许来源在 `config.yaml` 配置
- **CSRF**:每个会话签发 CSRF 令牌,前端在变更类请求头携带;JWT 走 Authorization 头本身免疫 CSRF,CSRF 作为纵深防御
- **SQL 注入**:全部使用参数化查询(ORM 或 `?` 占位),禁止字符串拼接 SQL
- **AES-256**:用户手动开启后,对敏感字段(如 QRZ 登录凭据、邮箱、地址等)以 AES-256-GCM 加密存储,密钥本地保管
- **输入校验**:所有 API 入参做类型与白名单校验

## 7. API 概述

- **请求方式**:统一 **POST**(查询与变更均 POST,请求体 JSON)
- **响应结构**:标准 JSON

```json
{
  "code": 200,
  "msg": "ok",
  "data": { }
}
```

常用状态码:`200` 成功、`400` 参数错误、`401` 未认证、`403` 无权限、`404` 不存在、`500` 服务器错误。

- 接口清单与字段详见独立文档 [API.md](API.md)
- 统一前缀 `/api/`,如 `/api/log/list`、`/api/qrz/lookup`、`/api/qsl/save`

## 8. 日志系统

- 由 **`backend/core/logger.py` 单一文件**统一记录全应用日志
- 用户可在配置中选择等级:`DEBUG / INFO / WARNING / ERROR / CRITICAL`
- **崩溃日志必保**:通过 `sys.excepthook`、`faulthandler`、全局异常拦截与 `atexit` 刷新,确保崩溃信息写入 `logs/crash.log`
- 插件审核与运行日志单独记入 `logs/plugin_audit.log`
- 文件按天轮转,默认保留 30 天

---

## 9. 授时同步

- 后端启动(或用户触发)时连接标准授时服务器(NTP,默认 `ntp.ntsc.ac.cn`、`pool.ntp.org`)
- **自动获取管理员权限**:Windows 下触发 UAC 提权,通过系统命令校正本机时间;Linux 下使用 `timedatectl`/`date`(需 sudo)
- 确保日志时间戳、UTC 转换、LoTW 上传时间准确

## 10. 插件系统

### 10.1 插件规范
- 插件以**英文文件夹名**命名,内含 `manifest.json` + 一个或多个 `.py` 文件
- `manifest.json` 声明:ID、名称、版本、作者、入口、最低应用版本、权限、敏感权限、API 版本
- 开发规范详见 [PLUGIN_DEV.md](PLUGIN_DEV.md)

### 10.2 加载流程
1. 扫描 `plugins/` 目录
2. 读取 `manifest.json`
3. **语法审核**:`ast.parse` + `py_compile`,失败则不加载并提示语法错误
4. 权限校验:敏感权限需用户在插件中心确认
5. 沙箱加载执行,业务隔离

### 10.3 插件中心
- 用户可添加第三方插件源(URL),内置官方默认源
- 支持浏览、安装、更新、启用/停用、卸载
- 敏感权限操作醒目提醒用户

### 10.4 隔离与稳定
- 插件运行于沙箱(子进程 + 超时 + 资源限制),异常被捕获
- 插件崩溃不影响主业务系统与数据库

## 12. 快速开始

### 环境要求
- Python 3.9+
- 现代浏览器(访问前端)

### 安装与运行
```bash
git clone https://github.com/ARPRC-BA8AQA/HamLog.git
cd HamLog
pip install -r requirements.txt
python run.py
```
浏览器打开 `http://127.0.0.1:5000` 即可使用。首次启动自动生成 `config.yaml` 与数据库。

### 可选
- 安装 TrustedQSL 以使用 LoTW 上传
- 在配置中开启认证/AES 加密/授时等
